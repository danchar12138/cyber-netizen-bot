# 赛博网友机器人开发计划

版本：2026-09-14-v27  
主题：渠道探测结果自动告警通知闭环  
状态：已完成

## 给 AI 的开发大纲

### 目标

将周期连接探测产生的 `connection.tested` 健康结果接入现有渠道告警和通知队列。探测任务完成后按当前 Agent 的已发布配置计算活动告警；仅在存在未抑制告警且通知目标、签名密钥和适配器均可用时创建通知任务。

### 已实现范围

- `AlertNotificationService` 新增 `enqueue_if_active`，复用配置校验、告警聚合、SecretStore 和可靠后台任务；无告警、通知关闭、目标未配置或密钥缺失时安全跳过。
- `ChannelConnectionProbeTaskHandler` 支持注入最小告警通知端口，在连接探测完成后触发自动通知入队。
- Worker 组合根创建告警通知服务，使用 `channel_alert_notification` 审计记录器和 `notification` 队列已有处理器。
- 通知任务仍只保存 Agent、适配器、告警安全摘要、幂等键和运行参数；目标地址与 Secret 在执行时从生效配置和 SecretStore 解析。
- 保留现有告警冷却时间、抑制/确认处置和任务去重语义，不新增敏感数据表。

### 安全与可靠性约束

- 自动触发不绕过显式通知配置；关闭通知或配置不完整不会导致探测任务失败。
- 任务和审计中不得出现 Webhook 地址、签名密钥、Bot Token、消息正文或远端原始错误。
- 告警通知沿用 PostgreSQL 任务真相、Outbox、租约、重试和 Dead Letter；相同告警摘要使用稳定幂等键去重。
- Worker 仅通过应用层端口访问告警服务，领域与认知包不依赖 Web 框架、ORM 或厂商 SDK。

### 验收标准

- 探测成功、未配置和降级结果均能安全完成；活动告警存在时产生 `notification_delivery` 任务。
- 无活动告警、通知关闭、通知目标缺失或签名密钥缺失时不产生通知任务。
- 通知任务不保存目标地址或 Secret，执行时仍能从配置中心和 SecretStore 解析运行时值。
- Python 测试、Pyright、Ruff、格式检查、Alembic heads 和 Web lint/typecheck/test/build 通过。

### 下一阶段

完善告警历史与趋势运营：增加告警通知状态查询、连续失败计数和恢复通知策略，并在管理后台提供可筛选的通知投递时间线。
