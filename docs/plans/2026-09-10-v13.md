# 赛博网友机器人增量开发计划

> 版本：2026-09-10-v13
> 阶段：用户访问策略与可信角色覆盖
> 状态：已完成

## 目标

- 在 v12 用户身份详情之上补齐临时停用、用户级请求限流和手工角色覆盖，形成真正可执行的访问治理闭环。
- OIDC 角色始终保留为可信基线；手工覆盖可设置期限、可显式撤销，且不能被下一次 OIDC 登录静默冲掉。
- 所有策略在服务端认证授权边界统一执行，管理后台只负责可解释展示和有确认的命令。

## 实现大纲

1. 为用户增加限流、临时停用和策略更新时间，为角色分配增加可信 OIDC 基线、手工覆盖操作者与到期时间，并建立每用户单行原子请求窗口；同步 ORM 与 Alembic 单 head。
2. 扩展纯领域访问策略、应用服务和仓储端口；内存及 PostgreSQL 实现租户隔离、逐字确认、状态冲突校验和不含凭证的安全审计。
3. 在认证后、权限判断前统一应用用户状态、临时停用、有效角色覆盖与请求预算；返回明确的 403/429 和 `Retry-After`，同一请求只计数一次。
4. 增加访问策略更新、角色覆盖和撤销 API；角色变更使用独立的管理员权限，运营者不得将自己或他人提升为管理员。
5. 扩展“用户与身份”详情面板，管理限流和临时停用，解释可信角色与当前生效来源，并对自我锁定或降权风险作显式提示。
6. 增加认证、应用服务、API、迁移与 Playwright 测试，并同步 OpenAPI、生成式 TypeScript SDK 和中文审计文案。

## 验收条件

- 已停用或仍在临时停用期的用户无法继续访问；超过用户级分钟预算时返回 429 和合法 `Retry-After`。
- 用户策略、限流窗口和角色覆盖严格按租户隔离；并发请求不能绕过预算。
- 只有管理员拥有角色覆盖权限；手工覆盖到期或撤销后恢复最近一次可信 OIDC 角色。
- OIDC 后续登录只更新可信基线，不会覆盖仍有效的手工角色；最终权限来自服务端持久化结果而非浏览器。
- 策略 API、审计、日志和页面不返回访问令牌、令牌摘要或原始 OIDC claim。
- Python、Web、Playwright、OpenAPI、Alembic 单 head、迁移升降级和远端 CI 全部通过。

## 暂不包含

- 不增加 IP、设备指纹、地理位置或行为风控画像；本阶段只治理已认证的本地用户主体。
- 不实现自助解封、审批流或角色自助申请。
- 不改变 OIDC 启动配置、内置角色能力矩阵和 MinIO 唯一对象存储边界。
