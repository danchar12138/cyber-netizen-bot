## 给 AI 的开发大纲

### 目标

在 v33 的通用告警活动、升级和恢复通知基础上，为可观测性管理后台补齐可执行的告警处置能力。确认、临时抑制和解除必须贯通领域、仓储、API、权限、审计与 Web，抑制状态必须真实阻止对应通用告警通知，而不是仅作为展示标签。

### 实现范围

- 新增按租户、Agent、来源类型和稳定来源键唯一的通用告警处置记录，支持已确认与临时抑制两种状态。
- 通用告警生命周期列表支持按状态、来源、严重级别和最短持续时间筛选，并返回当前有效处置摘要。
- 提供通用告警确认、临时抑制和解除 API；写操作要求显式确认、专用权限和 Agent 归属校验。
- PostgreSQL 处置写入与审计记录在同一事务完成；审计只保存安全标识、状态和到期时间，不保存告警通知目标、Secret 或业务正文。
- Worker 对活动、升级和恢复通知统一跳过仍在有效期内的抑制记录；已确认告警仍保留正常通知语义。
- 可观测性后台增加来源、级别和最短持续时间筛选，并提供确认、抑制与解除操作及明确反馈。

### 关键设计

- 处置按稳定来源键生效，可以覆盖同一来源重新活动后的新生命周期；过期抑制自动失效但保留审计历史。
- API 以生命周期 UUID 定位操作目标，服务端再解析稳定来源键，调用方不能借由自填键跨 Agent 操作。
- 新增 `observability_alert:manage` 权限并授予管理员与运营角色；只读角色只能查看筛选结果和处置摘要。
- 不新增只能手工维护的运行配置，不修改自研认知核心的框架边界，不引入外部副作用。
- 对象存储继续以 MinIO 为唯一实现和产品称谓，不引入 S3 或兼容后端。

### 验收标准

- 相同租户和 Agent 的同一来源仅保留一条当前处置记录，跨租户或跨 Agent 的生命周期与处置不可读取或修改。
- 临时抑制必须设置未来到期时间；未明确确认、空原因、无效时间和不存在的生命周期返回稳定错误。
- 有效抑制阻止通用活动、升级和恢复通知入队；抑制到期或解除后恢复通知行为。
- 生命周期查询的状态、来源、级别、持续时间筛选可以组合使用，Web 操作后会刷新当前 Agent 的列表和总览。
- 数据库 DDL、ORM、Repository、契约、OpenAPI、生成客户端、后台、权限标签和测试保持一致。
- `uv run poe check`、Alembic 单头、Web 完整检查和 `git diff --check` 全部通过。
