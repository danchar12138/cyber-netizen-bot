> 版本：2026-09-09-v2

## 一句话目标

开发一个以自研 Agent 为核心、具有稳定人格、长期记忆、关系连续性和主动行为能力的“赛博网友”；首发 Web 统一管理后台，内置全功能对话工作台，并为后续飞书、Discord、Telegram 等 IM 平台保留统一适配接口。除启动级配置外，日常管理尽量不要求手改配置文件。

## AI 开发约定

- 开始开发前先读取本文件和仓库中的 `AGENTS.md`。
- 当前只实现本计划范围；架构或范围发生明显变化时，新建 `docs/plans/YYYY-MM-DD-vN.md`，不要覆盖旧版本。
- 优先完成可运行的纵向闭环，再扩展拟人能力；每个阶段结束时保持应用可启动、测试可运行。
- 自研 Agent 核心不得依赖某个模型厂商、Web 框架或 Agent 编排框架。
- 模型只产生结构化行动候选；外部副作用统一经过权限、策略、预算和审计层。
- 配置、模型字段、API Schema、数据库迁移、客户端类型、测试和文档必须同步更新。
- 新增运行时能力时必须同时提供配置 Schema、默认值、管理 API 和后台表单；不要只增加环境变量或要求手改 YAML/JSON。
- 密钥不得明文回显。后台只允许写入、测试、轮换和清除密钥；读取时仅返回掩码及元数据。
- 使用标准 `uv` 工作流管理 Python；提交 `uv.lock`，不手工维护虚拟环境或 `PYTHONPATH`。
- 完成任务后删除临时脚本、实验目录、日志、测试上传物和其他中间文件。

## 技术栈

### 后端

- Python 3.12+。
- `uv workspace` 管理依赖、锁文件、构建和命令。
- FastAPI + Uvicorn。
- Pydantic v2 + pydantic-settings。
- SQLAlchemy 2 async + psycopg 3 + Alembic。
- 自研 `CognitiveRuntime`、`ModelProvider`、`ChannelAdapter` 和 `Tool` 接口。
- Dramatiq + Redis 执行后台任务。
- Ruff + Pyright strict + pytest。
- Poe the Poet 提供跨平台开发命令。

不把 LangChain/LangGraph 作为核心依赖。未来若确有必要，只能作为认知运行时的可替换实现。

### Web 管理后台

- React 19 + TypeScript strict + Vite。
- TanStack Router + TanStack Query。
- Zustand 只存 UI 临时状态。
- Tailwind CSS 4 + Radix UI。
- HTTP/JSON 发送命令，WebSocket 接收流式内容和状态事件。
- OpenAPI 自动生成 TypeScript 客户端。
- pnpm（通过 Corepack 固定版本）。
- Vitest + Testing Library + Playwright。

后台采用 Schema 驱动表单：后端以 Pydantic/JSON Schema 声明配置，前端根据 Schema 渲染基础控件，并允许复杂模块提供专用编辑器。这样新增 Provider、Tool 或 Adapter 时，不需要重复手写整套配置页面。

### 数据与基础设施

- PostgreSQL 16+：业务真相源。
- pgvector：语义记忆，与全文、时间、重要性和关系权重组成混合召回。
- Redis 7+：任务 Broker、短期锁、限流和临时状态，不保存唯一业务事实。
- MinIO（开发与生产）：附件和大对象的唯一对象存储。
- Docker Compose：本地开发基础设施。
- OpenTelemetry：日志、Trace 和指标关联。

### 配置管理

- PostgreSQL 保存运行配置及版本，是运行时配置的真相源。
- `Configuration Registry` 统一提供配置 Schema、默认值、作用域、敏感级别、校验和生效方式。
- 配置作用域支持系统、租户、Agent、渠道实例和用户，按明确优先级合并并能查看“最终生效值”。
- 普通运行配置支持草稿、校验、差异预览、发布、回滚、导入/导出和审计。
- 安全变更支持二次确认；高影响变更可先进行 dry-run、连接测试或小流量验证。
- 非敏感且安全的配置通过事件通知热更新；必须重启的配置应在后台明确标注，不得假装已经生效。
- 密钥经 `SecretStore` 抽象保存。默认自托管实现使用环境中的主密钥进行信封加密，生产可替换 Vault 或云密钥服务。
- `.env` 只保留数据库连接、Redis、对象存储、配置加密主密钥和首次管理员引导等启动级参数；其余配置通过后台维护。

## 核心模块

### 1. Agent 认知运行时

一次对话的标准流程：

1. `Perception`：提取意图、实体、情绪与社交线索，推断必须带置信度。
2. `Context Assembly`：按 token 预算组装人格、会话、用户、状态和记忆。
3. `Recall`：先按租户/用户/会话权限过滤，再混合检索记忆。
4. `Social Mind`：决定是否回应、关系距离、语气、主动程度和边界。
5. `Deliberation`：生成结构化行动候选，支持回复、追问、等待、不回复、工具调用和后续跟进。
6. `Policy Gate`：确定性校验权限、风险、预算、频率和是否需要确认。
7. `Response Realization`：根据已批准行动生成自然表达并流式输出。
8. `Reflection`：异步总结 Episode、长期记忆、关系变化和后续行动候选。

核心只依赖 Python 类型与 Protocol，不引用 FastAPI、SQLAlchemy、Dramatiq 或供应商 SDK。

### 2. 人格系统

- `Persona Constitution`：身份、价值观、行为边界和核心表达风格；人工版本化，模型不可直接改写。
- `Traits`：稳定特质，变化很慢并有上下限。
- `Affect State`：情绪、精力、压力、社交意愿和关注点，随事件变化并随时间衰减。
- `Self Narrative`：经过验证的自身经历与持续目标。
- `Relationship State`：针对每位用户分别维护熟悉度、信任、亲密、称呼、互动节奏、共同主题和边界。
- `Style Realizer`：调整句长、语气、幽默和表情，但不能修改事实或工具结果。

### 3. 记忆系统

记忆类型：工作记忆、情景记忆、语义记忆、关系记忆、自传记忆、程序性记忆。

每条长期记忆保存：主体与可见范围、内容与类型、来源消息、事件时间、置信度、重要性、情绪权重、敏感等级、确认状态、冲突/替代关系、embedding 模型版本。

召回综合考虑：

```text
语义相似度 + 关键词相关性 + 时间衰减 + 重要性
+ 关系相关性 + 时间连续性 - 不确定性惩罚
```

用户能够查看、纠正、遗忘记忆，并能禁止某个会话写入长期记忆。模型摘要不得冒充用户原话。

### 4. 模型层

- `ModelProvider` 统一支持流式、结构化输出、usage、超时、取消和能力描述。
- 快速模型负责分类、抽取、摘要和检索改写。
- 主模型负责社交判断、行动规划与回复表达。
- Embedding 模型负责记忆索引，支持版本化和渐进重建。
- 按能力、质量、延迟和预算路由，不在业务代码中按供应商名称分支。
- 具备超时、有限重试、熔断、降级和成本上限。

### 5. Channel Adapter

统一处理入站消息、编辑、撤回、反应和系统事件；统一输出发送、编辑、删除、反应、正在输入和线程回复等语义动作。

每个 Adapter 声明能力：文本、Markdown、图片、文件、流式、反应、线程、编辑和主动消息。Agent 只产生语义动作，由 Adapter 根据能力执行或降级。

本期内部 Web Chat Adapter 完整实现；IM 占位包只包含配置 Schema、能力声明、`not_configured` 健康状态和契约测试，不访问外部 API。后台提供渠道实例列表、配置表单、能力查看、启停、连接测试、健康状态和事件诊断页面，为正式接入 IM 做好管理入口。

### 6. 配置中心

- `Configuration Registry` 注册每个模块的配置键、JSON Schema、默认值、说明、作用域、是否敏感和热更新能力。
- `Effective Config Resolver` 根据系统 → 租户 → Agent/渠道 → 用户覆盖关系计算最终配置，并记录来源。
- `SecretStore` 隔离密钥的加密、读取和轮换；业务表只保存 secret reference。
- `Configuration Publisher` 负责草稿、校验、版本发布、变更事件和回滚。
- Runtime 在一次 Agent Run 开始时获取不可变配置快照，避免生成途中配置变化造成前后不一致。
- 每次 Run 记录有效配置版本、Persona 版本、Prompt 版本、模型路由版本和策略版本，保证可回放。
- 代码内只保留安全的内置默认值和启动配置；不得把日常运营参数散落为模块常量。

## Web 统一管理后台

Web 的主要定位是管理和运营整个赛博网友系统，对话页面只是一个内部调试及日常使用模块。后台尽可能覆盖所有运行功能，避免 SSH、数据库直改和手工维护配置文件。

### 管理模块

- **总览**：服务健康、活跃会话、Agent Run、模型用量/成本、任务积压、错误、渠道状态和近期告警。
- **Agent 与人格**：创建/复制/启停 Agent，编辑人格宪法、Traits、状态规则、表达风格、目标和版本；支持预览、测试和回滚。
- **模型与路由**：管理 Provider、端点、模型能力、参数模板、用途路由、预算、超时、重试、降级链和连接测试。
- **Prompt 与上下文**：管理 Prompt 模板、Context 预算、模块开关、版本差异和测试运行，保留每次发布版本。
- **内部对话**：提供完整对话页面，用于日常对话、Agent 调试、流式输出、附件、分支、反馈和记忆查看。
- **用户与身份**：管理用户、租户、角色权限、外部身份绑定、会话成员和封禁/限流状态。
- **会话与消息**：筛选、搜索、查看详情、归档、导出、软删除、定位异常 Run；敏感正文按权限遮罩。
- **记忆与关系**：搜索、筛选、查看来源、纠正、确认、遗忘、合并冲突、重建索引、查看关系变化。
- **工具与策略**：启停工具、编辑参数与权限、网络 allowlist、预算、审批条件、Policy 版本和模拟测试。
- **渠道与 Adapter**：管理渠道实例、配置、能力、凭证、启停、连接测试、健康检查、限流和事件诊断。
- **任务与主动行为**：查看队列、定时行动、重试、死信和执行历史；支持安全的取消、dry-run 与重放。
- **评测实验室**：管理评测集、运行对比实验、查看人格/记忆/边界指标和模型版本差异。
- **可观测性与审计**：查看 Agent Run 时间线、模型调用、工具调用、Trace 链接、配置变更和管理员操作。
- **系统设置**：管理运行参数、功能开关、数据保留、导入导出、备份状态和最终生效配置。

后台采用 `admin`、`operator`、`viewer` 等 RBAC；危险操作必须有清晰影响范围、二次确认和审计记录。

### 内部全功能对话页

- 位于管理后台内部，并复用后台的身份、权限、Agent 选择和调试能力。
- 左侧：Agent 切换、会话列表、新建、搜索、重命名、置顶、归档和删除。
- 中间：消息时间线、Markdown、代码、引用、图片、附件、流式内容、错误和工具状态摘要。
- 右侧抽屉：当前 Agent 状态、关系摘要、会话记忆、纠正/遗忘和隐私设置。
- 输入区：多行输入、草稿、快捷键、附件上传、发送、停止、失败重试。
- 消息操作：复制、引用、反馈、重新生成、编辑后创建分支。
- 连接能力：心跳、事件序号、断线恢复、多 Tab 一致性、重复事件去重。
- 状态：待发送、已接收、处理中、流式中、已完成、已取消、失败。
- 页面优先适配桌面，同时保证手机浏览器基本可用和键盘可访问。
- 不展示隐藏思维链；只展示清洗后的行动摘要、工具状态和可说明的记忆来源。

### 配置交互要求

- 所有可管理配置都提供字段说明、默认值、合法范围、当前值来源和是否需要重启。
- 保存前在客户端和服务端双重校验；连接类配置提供“测试但不发布”。
- 发布前显示差异和影响范围；发布后可查看历史并一键回滚到兼容版本。
- 密钥字段永不回填明文，允许覆盖、轮换、测试和清除，并记录操作者与时间。
- 配置依赖发生冲突时阻止发布并给出可执行错误，不允许静默忽略未知字段。
- 列表页提供筛选、分页、批量操作、导入导出；高风险批量操作必须二次确认。

## 异步任务

- `process_agent_run`：处理一次用户消息。
- `dispatch_outbox`：可靠发送消息和其他副作用。
- `extract_episode`：从一次 Run 中提取结构化经历。
- `consolidate_memory`：巩固、冲突检查和替代旧记忆。
- `embed_memory`：生成或重建向量。
- `update_relationship`：限幅更新关系状态。
- `evaluate_followup`：到期时重新判断是否适合主动跟进。
- `purge_deleted_data`：在保留期后同步删除数据库、向量和对象存储副本。

任务只传稳定 ID，必须幂等、可重试、可追踪。Redis 丢失后可依据 PostgreSQL 恢复必要任务；外部副作用使用 Transactional Outbox 防止丢失或重复。

## 最低质量要求

- 人格核心原则违反、未授权工具副作用、跨用户记忆泄漏、密钥/隐藏思维泄漏必须为 0。
- 每条长期记忆必须能追溯来源；推断不能记录成确定事实。
- 同一事件或任务重复执行不得造成重复回复或重复外部操作。
- Web 断线恢复后不得重复、丢失或回退已确认消息。
- Agent、模型、Persona、Prompt、检索和事件 Schema 均应版本化，以支持回放比较。
- 除启动级参数外，正式功能不得要求用户手工修改配置文件；后台配置必须可校验、审计、测试和回滚。
- 密钥不得通过普通配置 API 返回明文，也不得写入日志、Trace、导出文件或配置版本差异。
- 单元测试覆盖领域规则；集成测试覆盖数据库/队列；契约测试覆盖 Provider/Adapter；Playwright 覆盖主要用户路径。
- 每个阶段保持 Ruff、Pyright、pytest、TypeScript 和 Web 测试通过。
