# 赛博网友机器人开发计划

> 版本：2026-09-10-v6
> 阶段：入站消息到 Agent Run 纵向闭环
> 状态：已完成

## 目标

- 将已净化的 `InboundEnvelope v1` 转换为真实 Conversation 用户消息和 Agent Run。
- 平台重试、Worker 重投和人工重放共用确定性消息 ID，不重复生成消息、回复占位或 Run。
- 入站执行复用现有 `ConversationService`、认知运行时、模型路由、长期记忆和多模态链路。
- 将渠道作用域传入配置解析和模型凭证解析，使渠道级后台配置真实生效。

## 实现大纲

1. 严格解析并校验完整 Envelope；将平台内容块按原顺序投影为消息文本和附件引用。
2. 以租户、渠道和外部消息 ID 生成确定性 `client_message_id`。
3. 从附件仓储重新查询附件，校验租户、用户、会话、消息 ID、状态及持久化元数据，不信任 Envelope 声明。
4. 新增入站会话处理器，调用 `ConversationService.send_message()`、绑定附件并执行 Agent Run。
5. 已排队 Run 可恢复执行；终态 Run 直接幂等返回；中断的运行中 Run 安全失败并进入任务死信，不盲目重调模型。
6. 长时 Agent 任务执行期间主动续租数据库任务，避免模型运行超过静态租约后被恢复器并发重投。
7. Worker 组合 PostgreSQL 仓储、MinIO、配置密钥、模型 Provider、自研认知运行时及入站处理器。
8. Inbox 管理摘要仅增加内部消息与 Run 的安全状态，不暴露正文、附件对象键、密钥、Prompt 或模型原始响应。

## 验证与完成标准

- 覆盖首次入站、平台重试、Worker 重投、人工重放、渠道配置、非法附件和中断 Run。
- Python 使用 `uv` 完成格式、静态检查和测试；Web/OpenAPI 无漂移并保持可运行。
- 更新 README 与本计划状态，使用中文 Conventional Commit 提交并尝试推送 GitHub。

## 暂不包含

- 不调用飞书、Discord 或 Telegram 的真实 API。
- 不实现外部回复发送、编辑、撤回或平台媒体下载。
