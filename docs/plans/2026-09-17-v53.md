# 赛博网友机器人开发计划

版本：2026-09-17-v53

主题：拟人评测决策记录与可复现安全导出

状态：开发完成

## 给 AI 的开发大纲

### 目标

在 v52 同源基线差异基础上，允许管理人员人工选择候选与同源基线，并把决策时可见的聚合证据、样本门槛、观察差值、人工结论和理由冻结为不可变记录。报告后续可以按原始字节安全导出和校验，不因新增回放或盲评而漂移。

### 实现范围

- 增加评测决策领域类型、PostgreSQL 表、内存/PostgreSQL 仓储和审计记录。
- 创建时校验候选与基线属于同评测集键、同评测集版本、同 Provider/Model，且完整冻结快照不同。
- 复用 v52 的自动回归与盲评独立样本门槛，按创建时间截断并冻结双方聚合证据和差值。
- 支持“采纳候选、保持基线、等待更多证据”三种人工结论；理由必填，不触发自动调参、配置发布或其他副作用。
- 提供决策记录创建、列表、详情和 JSON 下载 API，同步 OpenAPI 与生成式 TypeScript SDK。
- 管理后台支持快照选择、决策填写、历史查看和带 SHA-256 的安全下载。
- 增加单元、API 集成、迁移、Web 单测和 Playwright 主路径覆盖。

### 关键规则

- 决策记录不可修改；需要改变结论时新建记录，保留完整历史。
- 候选与基线只按完整冻结快照聚合，创建后保存报告原始 JSON 字节和 SHA-256；导出不得重新计算。
- 自动回归和盲评继续分别要求双方至少 5 个样本，证据不足时对应差值为 `null`，但允许明确记录“等待更多证据”。
- 报告只包含租户/Agent 作用域内的版本元数据、安全聚合、人工结论和操作者元数据；不得包含输入、候选/参考回答、评审备注、Prompt、Secret 或隐藏推理。
- 列表与详情要求 `cognition:read`，创建要求 `cognition:evaluate`，下载还要求 `data_lifecycle:export`。
- Domain/Cognition 不依赖 FastAPI、SQLAlchemy、Dramatiq、MinIO SDK 或厂商 SDK。

### 验收标准

- 可从质量窗口选择两组同源且不同的完整快照并创建不可变决策记录；跨评测集版本或跨模型请求被服务端拒绝。
- 创建后新增回放或盲评不会改变既有记录；重复下载字节与 SHA-256 完全一致。
- 样本门槛、差值、人工结论、理由、冻结时间、操作者和非因果边界在 API、导出和 Web 中一致。
- 未持有导出权限的角色看不到下载入口且 API 返回拒绝；所有查询保持租户和当前 Agent 隔离。
- OpenAPI/SDK、数据库迁移、中文标签、测试与文档一致，无新增运行配置。
- Ruff、Pyright、pytest、Web lint/typecheck/test/build、Playwright、OpenAPI 漂移、迁移检查和 `git diff --check` 通过。
- 使用中文 Conventional Commit 提交并推送到 `origin/main`。

## 后续阶段

完成不可变决策记录后，再评估决策记录之间的审批流、签名证明和发布变更关联；仍不得根据观察差异自动调参或自动发布。
