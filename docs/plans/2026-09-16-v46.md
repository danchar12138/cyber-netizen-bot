## 给 AI 的开发大纲

### 目标

承接 v45 的回放证据绑定，让配置中心草稿和管理审计能够安全回溯校准来源。只保存回放窗口、配置版本、SHA-256 指纹、规则数量和合格反馈数量等聚合元数据，不保存原始反馈、消息正文、Prompt、隐藏推理、Secret 或任务载荷。

### 实现范围

- 为可观测应用服务增加框架无关的安全审计记录端口。
- 创建校准草稿成功后写入追加式审计事件，资源绑定到配置草稿。
- 在 API 组合根注入既有管理审计仓储，内存和 PostgreSQL 实现保持同一契约。
- 管理后台以现有审计日志页面展示中文动作名称和安全详情，不新增明文配置回显。
- 补充应用单测、API 集成测试、客户端/页面测试与计划进度记录。

### 关键规则

- 审计事件只能由服务端在回放指纹验证、配置版本校验和草稿创建成功后写入。
- 详情字段采用固定白名单，指纹只作为证据定位值，不作为授权凭证。
- 审计写入不得改变草稿发布边界；草稿仍需配置中心校验、人工审核和单独发布。
- Domain/Cognition 保持纯净，审计端口不依赖 FastAPI、SQLAlchemy、Dramatiq 或厂商 SDK。
- 任何异常、日志、导出和 UI 都不得暴露 Secret、正文、Prompt、任务载荷或模型原始响应。

### 验收标准

- 成功创建校准草稿后可在当前租户审计列表中查询到安全摘要，并绑定正确配置草稿 ID。
- 失败、过期、权限不足和跨租户请求不会写入校准草稿审计事件。
- OpenAPI、SDK、中文动作标签、单元测试、集成测试和管理后台保持一致。
- Ruff、Pyright、pytest、Web lint/typecheck/test/build、Playwright、OpenAPI 漂移、迁移 head 和差异检查通过。
- 使用中文 Conventional Commit 独立提交并推送到 `origin/main`。
