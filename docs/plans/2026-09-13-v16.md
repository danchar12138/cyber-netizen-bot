# 赛博网友机器人增量开发计划

> 版本：2026-09-13-v16
> 阶段：Telegram 安全入站 Webhook 与 Inbox/Agent Run 闭环
> 状态：开发中

## 目标

接通 Telegram Bot API 的真实入站消息：Webhook 请求完成密钥验证、载荷大小与时间边界校验、Update 归一化后，复用现有身份/会话映射和 Inbox/Agent Run 异步链路。公开接口不要求管理登录，不泄露 Bot Token、Webhook Secret、消息正文或 Telegram 原始响应。

## 实现范围

- Telegram Adapter 支持文本 `message` Update，覆盖私聊、群聊和 Forum 线程；机器人消息、频道消息、未知 Update、空文本、超长文本、非法 ID 和异常时间安全拒绝。
- 使用渠道级加密密钥 `telegram_webhook_secret` 校验 `X-Telegram-Bot-Api-Secret-Token`，提供管理端只写、轮换、清除和配置状态查看能力。
- 新增公开 `POST /api/v1/webhooks/telegram/{channel_id}`，限制请求体大小，调用 `ChannelService.normalize_inbound` 与 `InboundGatewayService.accept_normalized`，以 Telegram `update_id`/message ID 保证幂等。
- 保持租户、Agent、外部身份和会话映射严格隔离；重复 Update 不重复创建诊断事件、Inbox、消息或 Agent Run。
- 管理后台增加 Telegram 入站启用状态、Webhook Secret 状态/诊断和最近事件安全摘要；不显示正文与密钥。
- 同步 OpenAPI、生成式 TypeScript SDK、README、测试和中文产品文案；飞书、Discord 保持无外部副作用占位。

## 技术约束

- Python 依赖、测试、锁定和构建全部使用 `uv`；Domain/Cognition 不依赖 Web 框架、ORM、任务队列或厂商 SDK。
- Webhook 只接受 JSON，统一 UTF-8 与有限深度/字段长度；错误响应使用稳定中文业务错误，不回显原始请求或远端错误。
- SecretStore 是 Webhook Secret 唯一存储，任何 API、日志、Trace、导出和配置 diff 均不得返回明文。
- 复用现有 `ChannelInboundEvent`、`InboundVerification`、`accept_normalized` 和 Inbox 幂等实现，不新建平行入站流程。

## 交付顺序

1. 完成 Telegram Update 纯归一化函数与安全错误模型。
2. 增加 Webhook Secret 的应用服务、管理 API 与后台表单。
3. 实现公开 Webhook 路由、签名/大小/时间校验和闭环调用。
4. 增加 Adapter、Secret、API、幂等、隔离和前端测试。
5. 生成并校验 OpenAPI/TypeScript SDK，更新 README 与运行配置说明。
6. 运行 Python/Web/Playwright/静态检查、迁移与构建，使用中文 Conventional Commit 提交并推送。

## 验收

- 合法 Telegram 文本 Update 可创建一条安全 Inbox 并排队一个入站任务；重复请求返回同一 Inbox/Job 语义且无重复副作用。
- 缺失或错误 Secret、停用/未知渠道、跨租户或跨 Agent、机器人/频道/未知 Update、超限载荷均被拒绝。
- 诊断与管理页面只能看到状态、摘要和不可逆 digest；仓库无临时文件，工作区可直接启动 API、Worker 和 Web。
