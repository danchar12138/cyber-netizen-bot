# 赛博网友机器人开发计划

版本：2026-09-14-v25  
主题：Telegram 连接探测运维闭环与诊断筛选  
状态：已完成

## 目标

让管理后台能够快速查看 Telegram 等正式渠道最近的连接探测结果，并按安全事件类型筛选诊断记录；复用现有连接测试、健康快照和租户隔离边界，缩短凭证、限流、超时和平台不可用问题的定位路径。

## 开发范围

- 渠道诊断事件仓储和应用服务支持 `event_type` 精确过滤，限制长度并拒绝空白值。
- 诊断事件 API 增加可选 `event_type` 查询参数，跨租户、跨 Agent 过滤行为保持原有 404/空结果语义。
- Web 渠道管理页新增“最近连接探测”表格，展示渠道、探测结果、安全错误码和探测时间，不展示凭证、URL 或远端错误正文。
- 连接测试继续调用正式 Telegram Adapter 的 `getMe`，并把健康状态、错误码、时间写入既有 `connection.tested` 诊断事件和健康快照。
- 补充 Telegram API 限流连接测试、诊断过滤和服务层过滤回归测试；同步 OpenAPI 与 TypeScript 客户端。

## 安全与运行约束

- 连接测试是显式管理操作；常规消息投递仍通过渠道服务、能力协商、限流和幂等边界执行。
- 事件过滤只允许稳定事件类型，不接受任意 SQL 片段；查询始终附带租户、Agent 和渠道归属条件。
- API、UI、日志和审计不得返回 Bot Token、Secret、消息正文、Webhook URL 或 Telegram 原始响应。
- 连接测试失败只返回固定安全错误码和降级状态，原始平台错误描述不进入响应。

## 验收标准

- Telegram 成功、未配置、限流、超时和平台不可用场景均有 Adapter 或 API 回归覆盖。
- `GET /api/v1/channels/diagnostics/events?event_type=connection.tested` 仅返回连接探测事件，空窗口和无数据时稳定返回空列表。
- Web 渠道管理页可显示最近探测结果并在执行连接测试后刷新；不要求手动编辑配置文件。
- `uv run pytest -q`、`uv run pyright`、`uv run ruff check .`、`uv run ruff format --check .`、`uv run alembic heads` 通过。
- Web OpenAPI 生成、lint、typecheck、test、build 通过。
