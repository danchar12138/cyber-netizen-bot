# 赛博网友机器人开发计划

> 版本：2026-09-13-v18  
> 阶段：Telegram 入站运营化  
> 状态：开发中

## 目标

把 Telegram 入站链路从“部署侧手工注册 Webhook”提升为管理后台可观测、可操作的运营闭环，同时保持租户、Agent、渠道隔离和凭证/正文不回显。

## 开发范围

- Telegram Adapter 增加 `getWebhookInfo`、`setWebhook`、`deleteWebhook` 安全封装。
- 应用层增加 Webhook 状态查询、注册和清理用例；注册必须使用已加密的渠道 Webhook Secret，URL 只允许 HTTPS。
- 管理 API 增加 Webhook 状态、注册、清理接口，所有变更需要显式确认并记录诊断事件。
- Web 管理后台展示 Webhook 配置状态、待处理更新数、最近错误时间和允许的更新类型；支持注册/清理和刷新探测。
- 继续复用入站箱、出站诊断、任务死信和人工重放能力，不返回消息正文、Bot Token、Webhook Secret、远端原始响应或完整 URL。
- 同步 OpenAPI、TypeScript SDK、README 和单元/集成测试。

## 验收

- 无凭证、无 Webhook Secret、停用渠道、非 Telegram 渠道均不会访问 Telegram API。
- Webhook 注册只发送固定的 `message` 更新类型，并能安全处理 Telegram 错误、限流、网络失败和非法响应。
- 状态查询按租户和 Agent 隔离；跨租户/跨 Agent 只能得到 404。
- 重复注册、清理和刷新不会泄露密钥、URL 查询参数、远端错误正文或消息正文。
- `uv run pytest -q`、`uv run pyright`、`uv run ruff check .`、`uv run ruff format --check .` 以及 Web API 契约、lint、typecheck、测试和构建通过。

## 下一阶段

在本阶段完成后，继续补充 Telegram 运营指标聚合、失败出站事件的可控人工重试和告警通知策略。
