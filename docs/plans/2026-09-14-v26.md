主题：渠道连接探测周期化 Worker 垂直切片

## 给 AI 的开发大纲

### 目标

把渠道连接测试从管理后台的手动动作扩展为可恢复、可去重的周期任务。启用渠道按渠道级配置自动探测，复用 PostgreSQL 任务真相、事务 Outbox、租约、重试和 Dead Letter；任务结果只返回安全健康摘要。

### 已实现范围

- 新增 `channel_connection_test` 后台任务种类和 `channel` 队列映射。
- 新增 `ChannelConnectionProbeScheduler`：遍历启用渠道，读取 `channel.connection_probe_interval_minutes`，按 UTC 时间桶生成去重键并创建任务。
- 新增 `ChannelConnectionProbeTaskHandler`：校验任务载荷，调用 `ChannelService.test_connection`，只返回渠道 ID、健康状态和检查时间。
- Worker 注册 `channel` Dramatiq Actor、处理器和维护循环调度。
- Memory/PostgreSQL 渠道仓储提供启用渠道探测候选查询。
- 配置中心新增渠道级探测间隔，默认 15 分钟，范围 1-1440 分钟；禁止通过手工 config 文件管理。
- Alembic 更新 `ck_background_jobs_kind` 约束。

### 安全与可靠性约束

- 任务载荷只包含 Agent、渠道和审计操作者 UUID，不包含凭证、消息正文、Webhook URL 或远端原始错误。
- 连接测试继续通过 SecretStore 和 Adapter 正式健康检查执行。
- 同一租户、渠道和时间桶使用任务去重键，Worker 重启或重复维护循环不会重复创建任务。
- 仅查询启用渠道；禁用渠道不创建探测任务。

### 验收标准

- 启用渠道首次维护会创建 `channel_connection_test` 任务并进入 `channel` 队列。
- 最近一次检查未超过配置间隔时不创建任务；同一时间桶重复调度返回 0。
- 禁用渠道不会创建任务。
- 成功、未配置和降级结果均不泄露凭证或远端错误正文。
- 非法探测间隔和畸形任务载荷被拒绝或永久失败。
- Python 测试、Pyright、Ruff、格式检查、Alembic heads 和 Web 校验全部通过。

### 下一阶段

将 `connection.tested` 健康结果接入现有渠道告警策略：按连续失败次数和冷却窗口生成安全告警，投递至已配置通知适配器，并在管理后台展示告警状态和处置动作。
