# 赛博网友机器人开发计划

版本：2026-09-15-v37
主题：告警来源下钻与通知重放复核运营
状态：已完成

## 给 AI 的开发大纲

### 目标

在 v36 可追溯处置与重放守卫基础上，让管理人员从来源聚合直接下钻到完整、安全的生命周期记录，并能量化查看通用告警通知重放复核的允许与阻止结果。

### 实现范围

- 新增兼容现有列表接口的生命周期分页接口，使用 `updated_at + UUID` 不透明键集游标，支持状态、来源、级别和持续时间筛选。
- 来源健康聚合行可直接选择并联动下钻列表；Web 支持加载下一页，筛选或 Agent 变化时重置游标和选择状态。
- 新增追加式 `observability_alert_replay_reviews` 表，记录通用告警通知重放复核的操作者、来源、允许/阻止结论、稳定原因码和抑制到期时间，不保存任务载荷、通知目标、Secret 或业务正文。
- 重放守卫对格式不完整、Agent 归属冲突、有效抑制和允许重放分别记录复核事件；事件与通用审计在同一 PostgreSQL 事务内写入。
- 新增复核记录游标分页与窗口聚合 API，保持租户和当前 Agent 隔离；管理后台展示允许率、阻止原因、来源分布和近期记录。
- 同步 OpenAPI、生成 TypeScript 客户端、中文文案、运行手册与测试；不新增运行配置。

### 验收标准

- 生命周期分页无重复或遗漏，非法游标稳定返回 422，跨租户和跨 Agent 不可见。
- 每次通用告警通知重放复核都有一条安全事件；被阻止时不创建任务，允许时仍由任务仓储完成原有原子重放。
- 复核统计与列表使用同一安全事件表和筛选口径，空窗口返回零值，来源和原因计数与总计一致。
- API、Worker、Web、迁移、文档和生成客户端保持一致并通过完整检查。

### 后续阶段

- 为处置历史与复核历史增加保留期归档策略和导出能力。
- 增加告警运营指标的异常基线、值班交接摘要与自动化处置建议。
