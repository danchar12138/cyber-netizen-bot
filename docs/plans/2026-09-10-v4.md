# 赛博网友机器人增量开发计划

> 版本：2026-09-10-v4
> 状态：当前开发基线
> 基线：继承 `2026-09-09-v3.md` 已完成的 P0 至 P7 与第 6 至 11 项收口工作
> 当前阶段：渠道实例绑定 Agent 与入站路由隔离已完成

## 目标

在多 Agent 管理能力之上补齐渠道归属边界。每个 Web/飞书/Discord/Telegram 渠道实例必须明确且不可变地归属一个 Agent；管理后台随全局 Agent 选择只展示和操作该 Agent 的渠道、凭证与诊断事件，为后续接通真实 IM 时提供无歧义的消息路由。

本阶段不接入外部 IM API，不改变飞书、Discord、Telegram 的占位承诺，也不允许模型绕过策略门产生外部副作用。

## 硬约束

- Python 依赖、环境、锁、构建和命令全程使用 `uv`；Web 使用 Corepack 固定 pnpm。
- Domain 与 Cognition 不依赖 FastAPI、SQLAlchemy、Dramatiq、MinIO 或厂商 SDK。
- DDL、ORM、Repository、应用服务、API 契约、OpenAPI 客户端、Web、测试和文档同步修改。
- 客户端 Agent 选择不可信；所有渠道读写必须由服务端复核 UUID、租户归属、启用状态和渠道的 Agent 归属。
- 凭证明文、消息正文、文件名、对象键和远端原始响应不得进入 API 回显、日志、Trace、诊断事件、导出或异常。
- 新运行设置必须同时提供定义、验证、管理 API 和后台 UI；环境变量只保留启动参数与数据库可达前必需密钥。
- 每个纵向阶段保持 API、Worker 和 Web 可运行，并用中文 Conventional Commit 独立提交。

## 本阶段纵向切片

1. 数据归属（已完成）
   - `channel_instances` 增加非空 `agent_id` 外键。
   - 现有数据按同租户最早创建的 Agent 确定性回填；无法归属时迁移明确失败。
   - 名称唯一约束由租户级调整为 Agent 级，建立租户、Agent、平台、状态组合索引。
2. 领域与应用（已完成）
   - `ChannelInstance` 和安全响应增加 `agent_id`。
   - 渠道创建使用当前请求 Agent，不允许客户端另传归属。
   - 查询、更新、凭证、连接测试、发送模拟、入站模拟、限流和诊断事件都要求租户与 Agent 双重匹配。
3. API 与 Web（已完成）
   - 渠道路由接入统一 `get_request_identity`；`X-CNB-Agent-ID` 继续由生成客户端拦截器自动携带。
   - 渠道列表、详情与事件只返回当前 Agent 数据；跨 Agent ID 统一表现为资源不存在。
   - 渠道页 Query Key 纳入全局 Agent ID，切换后不复用旧 Agent 缓存；页面显示明确归属。
4. 验证（已完成）
   - 内存仓储与应用单测覆盖同租户跨 Agent 隔离。
   - API 集成测试覆盖创建归属、列表隔离、跨 Agent 更新/凭证/诊断拒绝。
   - Playwright 覆盖切换 Agent 后渠道列表刷新与请求头。
   - 更新 OpenAPI 3.1 和生成客户端，执行完整 Python/Web/Playwright/迁移质量门。

## 完成标志

- 任一渠道实例只有一个不可变 Agent 归属。
- 同租户两个 Agent 可以使用相同渠道名称且数据互不可见。
- 通过其他 Agent 选择访问已知渠道 ID、凭证或诊断记录均无法成功。
- 全局 Agent 切换后后台只展示所选 Agent 的渠道状态，不发生缓存串读。
- Alembic 保持单 head，全部质量门通过，README 与本计划记录实际完成状态。

## 后续顺序

2. Agent 完整生命周期管理：重命名、归档前影响预览、安全删除/保留策略。
3. 在真实 IM Adapter 仍保持占位的前提下，完善外部身份映射、会话线程映射与可重放入站 Inbox 契约。
4. 继续提高拟人性能：记忆写入判别、关系状态校准、长对话摘要与多模型回放评测。
