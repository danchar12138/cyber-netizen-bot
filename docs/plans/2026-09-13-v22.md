# 赛博网友机器人开发计划

版本：2026-09-13-v22  
主题：通知 Adapter 统一抽象与后台投递队列  
状态：已完成

## 目标

把告警通知从同步 HTTP 调用升级为可恢复的后台投递能力，统一邮件、飞书 Webhook 与通用 HTTPS Webhook 的 Adapter 边界，并让管理后台能够查看投递任务状态、尝试次数和安全失败码。

## 开发范围

- 在领域任务类型中增加 `notification_delivery`，复用现有 Inbox/Outbox、租约、指数退避和 Dead Letter。
- 增加厂商无关的通知 Adapter 协议、安全结果模型和注册表；保留通用 HTTPS Webhook，增加邮件与飞书 Webhook 实现。
- 告警通知任务 payload 只保存租户、Agent、操作者、时间窗、通知 Adapter 和配置引用，不保存 Secret、消息正文或远端响应。
- 增加通知任务 Handler，按任务冻结的安全摘要执行投递并返回安全结果；失败通过任务错误码与尝试记录观察。
- 管理 API 提供投递任务创建与任务状态查询，跨租户/Agent 访问继续隔离；OpenAPI、TypeScript SDK 和 Web 管理后台同步更新。
- 新增 Adapter、任务重试、SSRF、Secret 边界和真实协议传输桩测试。

## 安全与运行约束

- 领域层与认知层不依赖 FastAPI、SQLAlchemy、Dramatiq 或厂商 SDK。
- 通知目标、超时、重试、Adapter 选择等运行配置必须有定义、校验、管理 API 和后台 UI；Secret 只显示配置状态。
- HTTPS Webhook 仅允许安全 URL；邮件凭证通过 SecretStore；日志、审计、任务 API 和远端错误均不得暴露密钥或正文。
- 任务处理保持幂等，Adapter 返回稳定错误码和尝试摘要，原始响应只留在受控本地日志。

## 验收标准

- `uv run pytest -q`、`uv run pyright`、`uv run ruff check .`、`uv run ruff format --check .`、`uv run alembic heads` 全部通过。
- Web `check:api`、lint、typecheck、test、build 全部通过。
- 管理端创建通知任务后可看到 `pending/running/retrying/succeeded/dead_letter` 状态、尝试次数、下一次执行时间和安全错误码。
- 同一租户重复请求使用幂等键只产生一个任务；跨租户、跨 Agent 查询返回 404/403。
- Webhook、邮件、飞书 Adapter 的成功、限流、超时、网络失败和未配置场景均有测试覆盖。
