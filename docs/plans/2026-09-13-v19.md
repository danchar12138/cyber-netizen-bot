# 赛博网友机器人开发计划

> 版本：2026-09-13-v19
> 阶段：渠道运营指标与失败出站治理
> 状态：开发中

## 目标

把 Telegram 渠道从“能注册 Webhook、能查看单条诊断事件”提升为可持续运营的指标视图：管理后台可以按租户、Agent 和时间窗查看入站/出站量、成功率、失败与限流数量及最近失败时间；失败出站仍通过已有任务死信和人工重放闭环处理，不保存或回显消息正文。

## 开发范围

- 领域层增加渠道运营指标值对象，定义稳定的计数、失败率和时间窗语义。
- Channel Repository 增加按租户 + Agent + 渠道 + 时间窗聚合的内存与 PostgreSQL 实现，避免返回诊断载荷。
- Application/API 增加渠道运营指标查询接口，校验时间窗范围并保持租户、Agent 隔离。
- Web 管理后台在渠道页面展示指标、失败率、限流量和最近失败时间；失败任务继续跳转任务页执行显式确认重放。
- 对失败出站建立确定性告警提示和安全操作边界：不返回 Bot Token、Webhook Secret、完整 URL、远端错误正文或消息正文。
- 同步 OpenAPI、TypeScript SDK、README 与单元/集成测试。

## 验收

- 指标查询只返回聚合数值和时间戳，跨租户/跨 Agent/未知渠道不能读取数据。
- 入站、出站、成功、失败、限流和降级计数在内存仓储与 PostgreSQL 仓储语义一致；窗口边界包含两端。
- 失败率在无出站事件时为 0；最近失败时间只来自失败或限流事件。
- Web 页面可识别高失败率渠道，并引导管理员到任务页使用显式确认重放；任何页面不显示消息正文或凭证。
- `uv run pytest -q`、`uv run pyright`、`uv run ruff check .`、`uv run ruff format --check .`、`uv run alembic heads` 及 Web API 契约、typecheck、lint、测试和构建通过。
