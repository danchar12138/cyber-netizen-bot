# 赛博网友机器人开发计划

版本：2026-09-14-v24  
主题：统一可观测性看板接入渠道出站与通知投递指标  
状态：已完成

## 目标

将渠道出站投递和告警通知后台任务纳入现有租户级可观测性窗口，管理后台能够直接观察成功、降级、失败、限流、重试和死信状态，并基于已发布配置产生确定性告警。

## 开发范围

- 领域层新增渠道出站聚合和通知投递任务聚合，计算出站失败率时同时计入失败、拒绝和限流事件。
- PostgreSQL 仓储按租户、时间窗口和出站方向聚合 `channel_diagnostic_events`，按 `notification_delivery` 任务类型聚合 `background_jobs`，不读取或返回消息正文、凭证和远端原始响应。
- 可观测性服务增加渠道失败率告警和通知死信告警，阈值复用后台配置中心的 `alerts.channel.failure_rate_percent`。
- API 契约、OpenAPI 文档和 TypeScript 客户端同步新增字段；Web 管理后台展示渠道失败率和通知任务状态卡片。
- 补充服务层和 API 回归测试，锁定租户隔离、默认零值、失败率计算和告警代码。

## 安全与运行约束

- 仅聚合诊断事件和任务状态计数，禁止把 payload、正文、Secret、Token、密码或原始平台响应写入指标响应、日志和告警。
- 所有查询必须带租户过滤和明确时间窗口；通知任务仅统计 `kind=notification_delivery`。
- 内存仓储在无数据库联调时返回稳定的零值指标，保持 API 与 Web 可运行。
- 新增阈值沿用配置定义、校验、管理 API 和管理后台，不要求手动编辑配置文件。

## 验收标准

- `uv run pytest -q`、`uv run pyright`、`uv run ruff check .`、`uv run ruff format --check .`、`uv run alembic heads` 通过。
- Web lint、typecheck、test、build 通过，OpenAPI 与 TypeScript 生成文件已同步。
- 可观测性 API 始终返回 `channel_delivery` 和 `notification_delivery`，无数据时所有计数为零。
- 渠道出站失败率超过已发布阈值时产生 `channel_delivery_failure_rate` 告警；存在通知死信时产生 `notification_delivery_dead_letters` 告警。
- 新增测试不泄露任何消息正文或凭证字段。
