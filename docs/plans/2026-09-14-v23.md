# 赛博网友机器人开发计划

版本：2026-09-14-v23  
主题：主动行为到 IM 出站消息闭环  
状态：已完成

## 目标

让经过社交策略批准的 `proactive_message` 定时行为真正通过统一渠道服务投递，复用能力协商、幂等键、限流、凭证隔离和渠道诊断事件；管理后台可直接配置主动消息的渠道、收件人和正文，不再要求手动编辑任务载荷。

## 开发范围

- 主动行为 Worker Handler 解析并校验 `channel_id`、`recipient_id`、`message`、线程/编辑参数和流式标记。
- 批准的主动消息调用 `ChannelService.deliver`，使用稳定的行为 ID 幂等键，结果仅返回状态、外部消息 ID 和降级摘要。
- 任务在策略已标记为 `dispatched` 后重试时仍执行幂等投递，避免 Worker 在投递后崩溃造成消息丢失或重复发送。
- 非主动消息行为保持原有策略评估语义；占位 IM Adapter 由统一渠道层报告未配置错误，不访问外部平台。
- Web 管理后台的定时行为表单支持选择已启用且支持主动消息的渠道、填写收件人标识和消息正文，并展示渠道读取错误。
- 增加主动消息投递成功、重试、载荷校验和正文脱敏测试；保持领域层与认知层不依赖 Web 框架、ORM、Worker 框架或厂商 SDK。

## 安全与运行约束

- 任务载荷不得包含 Secret、Token、密码、凭证或远端原始响应；消息结果不回显正文。
- 目标渠道必须由 `ChannelService` 按租户和 Agent 归属校验，凭证仅在渠道服务内部从 SecretStore 解析。
- 主动投递必须声明 `proactive=True`，由 Adapter 能力协商拒绝不支持主动消息的平台。
- 所有投递继续写入出站诊断事件，沿用限流和幂等语义；不在 API 请求内访问第三方平台。

## 验收标准

- `uv run pytest -q`、`uv run pyright`、`uv run ruff check .`、`uv run ruff format --check .`、`uv run alembic heads` 全部通过。
- Web lint、typecheck、test、build 全部通过；OpenAPI/TypeScript 生成文件无额外差异。
- 策略批准的主动消息可投递到 Web/Telegram 等已实现渠道，返回安全投递摘要；同一任务重试只产生一个渠道副作用。
- 缺少渠道、收件人或正文时任务在策略评估前以永久错误结束；结果和日志不包含消息正文以外的敏感字段。
- 跨租户或跨 Agent 渠道 ID 无法投递；占位平台不发起网络请求。
