# 赛博网友机器人增量开发计划

> 版本：2026-09-10-v9
> 阶段：多模型同源回放与并列质量对比
> 状态：已完成

## 目标

- 使用同一评测集、配置、人格、Prompt、策略和模型路由快照，对多个已发布模型档案执行可重复的同源回放。
- 持久化一次对比实验及其候选运行关联，集中比较通过率、延迟、Token、成本和逐用例回答。
- 只允许选择当前 Agent 已发布 `chat.realizer` 路由引用的模型档案，禁止通过 API 绕过模型治理直接提交任意 Provider 或模型名。
- 在评测实验室完成候选选择、运行历史和逐用例并列查看，常用操作无需手改配置或直接访问数据库。

## 实现大纲

1. 为解析后的模型路由档案补充不可变档案键与版本，并提供当前可比较目标的只读 API。
2. 新增对比实验与候选运行关联领域类型、PostgreSQL 表、内存/SQLAlchemy 仓储和单头 Alembic 迁移。
3. 评测服务一次解析并冻结全套运行资源，对 2 至后台配置上限个档案运行同一用例快照；用例事件 ID 在候选间保持确定性一致。
4. 新增创建、列表和详情 API；返回每个候选的门禁、用量、成本、延迟及完整逐项结果，并保持租户与 Agent 双重隔离。
5. 评测后台展示可选模型档案、对比历史、指标卡和同一用例的并列回答；沿用现有权限、错误处理和中文显示层。
6. 新增每次对比最大候选数配置定义，复用配置 Schema、验证、发布、回滚、管理 API 和后台表单。

## 验证与完成标准

- 覆盖路由候选发现、无路由/候选不足/重复或越权档案拒绝、候选数量上限和冻结资源一致性。
- 覆盖同源事件、各候选独立用量与成本、内存与 PostgreSQL 持久化映射、租户/Agent 隔离和 API 契约。
- Playwright 覆盖后台选择两个模型、运行对比、查看指标与逐用例回答。
- 日志、Trace、审计和列表摘要不新增 Prompt、凭据、对象键或模型原始响应；完整回答只在受评测权限保护的详情接口返回。
- Python 使用 `uv` 通过格式、Ruff、Pyright 和全量测试；Web 通过类型、测试、构建和 Playwright；Alembic 保持单 head。
- README 与计划状态同步，并使用带中文描述的 Conventional Commit 独立提交。

## 暂不包含

- 不使用模型裁判自动宣称主观质量胜负；人格自然度仍由现有匿名人工盲评与确定性门禁共同判断。
- 不将候选模型临时写入正式路由，也不绕过现有 SecretStore、预算、超时和模型能力边界。
- 不接入真实飞书、Discord 或 Telegram API。
