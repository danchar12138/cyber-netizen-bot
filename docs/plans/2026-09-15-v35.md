主题：通用告警生命周期聚合与趋势查询
状态：已完成

## 给 AI 的开发大纲

### 目标

在 v34 通用告警筛选与处置闭环基础上，增加独立的通用生命周期聚合查询。统计直接基于通用告警生命周期安全数据，不能复用渠道告警指标口径；管理后台按当前筛选条件展示来源对比和时间桶趋势。

### 实现范围

- 增加通用告警生命周期指标领域模型，返回窗口汇总、来源分组、恢复耗时和固定时间桶趋势。
- 应用服务校验统计窗口、时间桶、来源和严重级别，并保持 UTC、租户与 Agent 隔离。
- 内存仓储与 PostgreSQL 仓储提供同名窗口查询端口；SQL 查询必须下推租户、Agent、来源和级别条件。
- 增加 `GET /api/v1/observability/alert-lifecycles/metrics`，只读权限沿用 `trace:read`，不返回正文、通知目标、Secret 或原始任务载荷。
- Web 可观测性页改用通用指标接口，展示来源健康对比、开启/恢复/升级趋势和恢复耗时；筛选条件与列表、指标联动。
- 同步 OpenAPI、TypeScript SDK、中文权限/界面文案与单元/API 测试，不新增运行配置或迁移。

### 关键设计

- 窗口内纳入活动生命周期，以及窗口内开启、恢复或升级的已恢复生命周期；事件落入固定桶，窗口尾桶承接不足一个完整桶的时间。
- P95 使用确定性 nearest-rank 计算，空样本返回 0；来源聚合与总计使用同一行集合，避免指标口径漂移。
- 来源和严重级别筛选在仓储查询层执行，应用服务只负责规范化输入和安全聚合。
- 统计接口与渠道生命周期接口保持独立命名和数据来源，未来可分别扩展缓存、下钻和历史归档。
- MinIO 继续作为唯一对象存储实现；本阶段不接入任何 S3 或兼容后端。

### 验收标准

- 相同租户和 Agent 的窗口统计只包含其生命周期；跨租户或跨 Agent 数据不可见。
- 窗口、时间桶、来源和级别参数非法时返回稳定 422；来源/级别筛选能同时影响总计、来源聚合和趋势。
- 总计与来源聚合的活动、开启、恢复、升级、平均恢复和 P95 恢复值一致，空窗口返回完整空桶序列。
- API 契约、OpenAPI、生成客户端、Web 页面和测试保持一致，不再调用渠道生命周期指标接口。
- `uv run poe check`、Alembic 单头、Web 完整检查和 `git diff --check` 全部通过。
