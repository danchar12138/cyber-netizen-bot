# 赛博网友机器人开发计划

版本：2026-09-14-v28
主题：告警通知状态、连续失败与恢复通知闭环
状态：已完成

## 给 AI 的开发大纲

### 目标

复用 `background_jobs` 中的可靠通知任务真相，为当前 Agent 提供不含目标地址、密钥和通知正文的投递时间线；支持按状态、通知适配器和事件类型筛选，并确定性计算连续失败次数。在周期探测确认此前已成功通知的活动告警全部恢复后，按后台运行配置自动且仅一次投递恢复通知。

### 实现范围

- 扩展任务仓储端口，按租户和 Agent 查询通知投递任务，数据库过滤必须先于数量限制。
- 在应用层生成安全的通知投递时间线和汇总，公开适配器、事件类型、状态、尝试次数、安全错误码、结果数值与时间，不公开任务原始载荷。
- 新增渠道通知时间线 API，支持状态、适配器、活动告警/恢复事件和数量筛选。
- 新增 `alerts.notification.recovery_enabled` Agent 运行配置；配置注册表、校验、管理 API 和通用配置后台保持同步。
- 自动通知在无活动告警时检查同一适配器最近一次成功的生命周期通知；仅当前序事件为活动告警且恢复通知启用时，创建幂等恢复通知。
- 管理后台渠道页新增通知状态汇总、连续失败指标和可筛选投递时间线。

### 安全与可靠性约束

- 时间线按当前租户与当前 Agent 双重隔离；筛选和数量限制不得造成跨 Agent 数据混入。
- API、Web、审计与日志不返回通知目标、Secret、原始任务载荷、远端响应正文或消息正文。
- 恢复通知只基于已成功投递的活动告警通知触发；待处理、失败和死信通知不能制造虚假恢复。
- 恢复通知使用前序活动通知构造稳定幂等键，重复探测不得产生重复外部副作用。
- PostgreSQL 仍是通知状态真相源，Redis/Dramatiq 只负责投递；不新增重复状态表。

### 验收标准

- 通知时间线只返回当前 Agent 的安全投影，状态、适配器和事件类型筛选有效。
- 成功通知清零连续失败计数；失败和死信按时间顺序递增，非终态不伪造成功或恢复。
- 前序活动通知成功且当前无活动告警时只创建一条恢复通知；关闭恢复开关或最近成功事件已是恢复时跳过。
- Web 可查看通知总量、成功、处理中、失败/死信、当前连续失败，并筛选投递时间线。
- Python 测试、Pyright、Ruff、格式检查、Alembic heads 和 Web lint/typecheck/test/build 通过。

### 下一阶段

增加告警事件级持久化生命周期、首次发生/恢复耗时统计和通知升级策略，并将趋势数据接入可观测性总览。
