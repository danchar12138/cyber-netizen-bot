# 赛博网友机器人开发计划

> 版本：2026-09-09-v3  
> 状态：当前开发基线  
> 用途：供 AI 开发前完整读取，也供开发者快速查看方向、约束与进度  
> 相对 v2：对象存储统一为 MinIO，使用 MinIO 官方 SDK；不接入 AWS S3，也不保留 S3 实现  
> 当前进度：P1 至 P7 已完成；P0 的 Docker 实跑、备份恢复实操证据和 GitHub `main` 保护仍待具备相应环境后验证。

## 一句话目标

开发一个由自研 Agent 主导、拥有稳定人格、长期记忆、关系连续性与主动行为能力的“赛博网友”。首发产品是 Web 统一管理后台，其中包含全功能内部对话工作台；后续飞书、Discord、Telegram 通过统一 Adapter 接入。除数据库、Redis、MinIO、配置主密钥等启动级参数外，日常功能都应在后台可管理。

## 开发硬约束

- 开发前读取本文件与仓库 `AGENTS.md`；架构或范围再变化时新建计划版本，不覆盖历史计划。
- Python 依赖、环境、锁文件、构建和命令全部使用 `uv`，提交 `uv.lock`。
- 前端通过 Corepack 固定的 pnpm 工作流管理。
- 领域层与认知层不得依赖 FastAPI、SQLAlchemy、Dramatiq、MinIO SDK 或模型厂商 SDK。
- 模型只能提出结构化行动候选；权限、策略、预算、审批、外部副作用与审计由确定性代码控制。
- 新运行设置必须同步提供配置定义、校验、管理 API 与后台 UI；环境变量只用于数据库可用前的启动设置和密钥。
- DDL、ORM、Repository、API 契约、客户端类型、路由、测试与文档必须同步。
- 所有密钥禁止通过 API、日志、Trace、导出、差异或异常明文回显。
- 中文是默认开发与用户语境：文档、注释、用户提示、错误、测试描述与提交说明优先使用自然中文；标准协议字段、代码标识符和第三方专有名词保持行业惯例。
- 每个纵向阶段必须可运行、测试通过、清理中间产物，并使用带中文说明的 Conventional Commit 独立提交。

## 范围

### 本期实现

- 自研 Agent 认知运行时。
- Web 统一管理后台及全功能内部对话工作台。
- Agent、人格、模型、Prompt、记忆、关系、工具、策略、渠道、任务、评测、用户和系统设置的可视化管理。
- 配置版本、双端校验、差异、发布、回滚、连接测试、密钥管理与审计。
- PostgreSQL 16 + pgvector 作为业务与长期记忆真相源。
- Redis 7 + Dramatiq 承载可恢复异步任务。
- MinIO 作为唯一附件与大对象存储；开发与生产均使用 MinIO，应用通过 MinIO 官方 Python SDK 访问私有桶。
- WebSocket 流式事件、心跳、序号、去重与断线恢复。
- Web Channel Adapter 正式实现，飞书/Discord/Telegram 仅做契约与占位。
- 自动测试、回放评测、Docker Compose、GitHub Actions 与发布流水线。

### 暂不实现

- 原生桌面与移动 App。
- 第三方 IM 的真实外部连接。
- AWS S3 或其他云对象存储实现。
- 多 Agent 社会、知识图谱、Kafka、Kubernetes、独立向量数据库。
- 未经过策略层的主动消息、高风险工具或外部副作用。
- 完整实时语音；先保留多模态协议，优先文本、图片与文件。

## 技术栈

### 后端与核心

- Python 3.12+、uv workspace、Poe the Poet。
- FastAPI、Uvicorn、Pydantic v2、pydantic-settings。
- SQLAlchemy 2 async、psycopg 3、Alembic。
- 自研 `CognitiveRuntime`、`ModelProvider`、`ChannelAdapter` 与 `Tool` Protocol。
- Dramatiq + Redis。
- MinIO 官方 Python SDK；浏览器使用短期预签名 URL 直传私有桶，API 复核大小、媒体类型与 SHA-256。
- Ruff、Pyright strict、pytest。

不使用 LangChain/LangGraph 作为核心。若未来需要，只能作为可替换适配实现，不能污染领域协议。

### Web 管理后台

- React 19、TypeScript strict、Vite。
- TanStack Router、TanStack Query；Zustand 仅用于必要的本地 UI 状态。
- Tailwind CSS 4、Radix UI。
- HTTP/JSON 命令 + WebSocket 事件。
- OpenAPI 生成 TypeScript 客户端。
- Vitest、Testing Library、Playwright、axe 无障碍检查。
- 桌面优先，同时保证手机基本可用、键盘可操作、焦点清晰、减少动态效果设置有效。

### 配置与基础设施

- PostgreSQL 保存运行配置及版本，是运行配置真相源。
- 配置作用域为系统、租户、Agent、渠道实例、用户，按明确优先级合并并展示最终来源。
- 普通配置支持草稿、校验、差异、发布、回滚、导入导出与审计。
- 密钥由 `SecretStore` 信封加密保存；后台只允许写入、测试、轮换和清除。
- `.env` 仅保留数据库、Redis、MinIO 连接与凭证、配置主密钥和首次管理员引导。
- MinIO 桶必须私有，由 Compose 初始化任务幂等创建；浏览器直传 CORS 通过启动配置声明。
- Redis 丢失后可从 PostgreSQL 恢复必要任务，不能保存唯一业务事实。
- OpenTelemetry 关联结构化日志、Trace、指标和请求/运行 ID。

## 总体架构

```text
Web 管理后台（含内部对话）
  │ HTTP 命令 / WebSocket 事件 / MinIO 预签名直传
  ▼
FastAPI Gateway
  ├─ Auth / RBAC / Rate Limit / Idempotency
  ├─ Configuration / Secret / Audit
  ├─ Administration / Conversation / Attachment
  └─ Inbox / Transactional Outbox
          │
          ▼
自研 Cognitive Runtime
  Perception → Context Assembly → Memory Recall → Social Mind
  → Deliberation → Policy Gate → Tool Execution
  → Response Realization → Async Reflection
          │
          ├─ PostgreSQL + pgvector
          ├─ Redis + Dramatiq
          ├─ MinIO
          └─ Model Providers

Channel Adapter
  ├─ Internal Web Chat（正式）
  ├─ Feishu（占位）
  ├─ Discord（占位）
  └─ Telegram（占位）
```

采用模块化单体；API 与 Worker 分进程。没有经过性能与组织边界验证前不拆微服务。

## 核心设计

### 认知与人格

一次运行依次经过感知、上下文组装、记忆召回、社交心智、结构化决策、策略门、表达和异步反思。人格由人工版本化的宪法、缓慢变化的 Traits、可衰减情绪状态、自我叙事、用户独立关系状态和不改变事实的表达器组成。系统必须能选择回复、追问、等待、不回复、工具调用与后续跟进，且所有推断带置信度。

### 记忆与关系

支持工作、情景、语义、关系、自传、程序性六类记忆。长期记忆必须保存租户与可见范围、来源、事件时间、置信度、重要性、情绪权重、敏感等级、确认状态、冲突/替代关系和 embedding 版本。召回组合语义、全文、时间、重要性、关系和连续性。用户可查看、纠正、确认和遗忘；模型摘要不得冒充原话。

### 模型、工具与策略

`ModelProvider` 统一流式、结构化输出、usage、超时、取消与能力描述；路由依据用途、能力、质量、延迟与预算，支持有限重试、熔断、降级和成本上限。Tool 只暴露类型化输入输出，执行前由 Policy Gate 检查权限、网络 allowlist、风险、预算、频率与审批。

### Channel Adapter

统一入站消息、编辑、撤回、反应与系统事件，统一发送、编辑、删除、反应、输入状态与线程回复。Adapter 声明文本、Markdown、图片、文件、流式、反应、线程、编辑和主动消息能力；缺失能力必须透明降级。占位 Adapter 不访问外部 API，只返回明确的 `not_configured` 健康状态。

### 内部对话工作台

- 左侧：Agent 切换、会话列表、新建、搜索、重命名、置顶、归档与删除。
- 中间：消息时间线、Markdown、代码、引用、图片、文件、状态、失败与工具摘要。
- 右侧：Agent 状态、关系摘要、会话记忆、纠正/遗忘与隐私设置。
- 输入：自动保存草稿、快捷键、MinIO 附件上传与进度、发送、停止、重试。
- 操作：复制、引用、反馈、重新生成、编辑后创建独立分支。
- 连接：心跳、事件序号、重连回放、重复事件去重、多 Tab 查询一致性。
- 不展示隐藏思维链，只展示清洗后的行动摘要、工具状态和可说明来源。

### 主要数据实体

- 身份：`tenants`、`agents`、`users`、`external_identities`。
- 对话：`conversations`、`conversation_members`、`messages`、`message_parts`、`attachments`、`message_feedback`。
- 运行：`agent_runs`、`run_steps`、`goals`、`action_candidates`、`model_invocations`、`tool_calls`。
- 人格关系：`persona_versions`、`persona_state_snapshots`、`relationships`、`relationship_events`。
- 记忆：`episodes`、`memories`、`memory_sources`、`memory_links`、`memory_embeddings`。
- 可靠性：`inbox_events`、`outbox_events`、`scheduled_actions`、`job_attempts`、`audit_logs`。
- 配置：`configuration_versions`、`configuration_values`、`secret_references`、`feature_flags`。
- 模型渠道：`model_providers`、`model_profiles`、`model_routes`、`channel_instances`、`tool_definitions`、`policy_versions`。
- 权限：`roles`、`permissions`、`role_assignments`、`admin_sessions`。

所有业务表从第一天保留租户隔离与幂等设计。

## 最低质量门槛

- 人格核心原则违反、未授权副作用、跨用户数据泄漏、密钥或隐藏思维泄漏必须为 0。
- 每条长期记忆可追溯来源；推断不能伪装为确定事实或用户原话。
- 同一事件、命令与任务重放不产生重复消息或外部操作。
- 断线或多 Tab 恢复后不重复、不丢失、不回退已确认消息。
- Agent、Persona、Prompt、模型路由、检索、策略和事件 Schema 全部版本化。
- 除启动参数外，正式功能不得要求手改文件；后台设置可校验、审计、测试和回滚。
- 单元测试覆盖领域规则，集成测试覆盖持久化与队列，契约测试覆盖 Provider/Adapter，Playwright 覆盖主要路径。
- 每次阶段提交前保持 Ruff、Pyright、pytest、前端 lint/typecheck/unit/build、Playwright 与迁移检查通过。
