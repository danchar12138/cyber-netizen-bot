# 赛博网友机器人开发计划

版本：2026-09-14-v29
主题：告警事件生命周期、升级策略与可观测趋势
状态：已完成

## 给 AI 的开发大纲

### 目标

将当前按窗口即时计算的渠道告警扩展为 PostgreSQL 持久化的事件生命周期。周期探测后原子对账活动告警，记录首次发生、最近发生、恢复时间、恢复耗时和升级状态；按 Agent 运行配置对持续未恢复事件执行一次稳定幂等的升级通知，并在渠道管理与可观测性总览中提供安全历史和趋势数据。

### 实现范围

- 新增租户与 Agent 双重隔离的渠道告警生命周期模型、迁移、领域类型和 Memory/PostgreSQL 仓储实现。
- 周期连接探测完成后，以稳定告警键原子开启、更新和恢复生命周期；同一告警恢复后再次发生时创建新事件。
- 渠道错误聚合补充窗口内首次发生时间；健康降级生命周期使用连续降级快照的起点。
- 新增 `alerts.notification.escalation_enabled` 与 `alerts.notification.escalation_after_minutes` Agent 配置，并保持定义、校验、管理 API 和通用配置后台同步。
- 持续活动告警超过阈值时标记升级，并使用生命周期 ID 构造稳定幂等通知；通知时间线支持升级事件。
- 新增可筛选告警生命周期 API，在渠道管理后台展示状态、严重级别、首次/最近发生、持续或恢复耗时及升级状态。
- 可观测性总览增加告警生命周期聚合和趋势点，展示窗口内开启、恢复、升级、活动事件及平均/P95 恢复耗时。

### 安全与可靠性约束

- 生命周期和趋势查询必须先按租户和 Agent 过滤再限制数量，不保存或返回消息正文、外部目标、Secret、远端响应正文或原始任务载荷。
- 活动事件对账必须在单个数据库事务内完成；并发探测不得创建重复活动生命周期，已恢复事件不得被原地重新打开。
- 升级通知仅针对达到持续时间阈值的活动事件，使用生命周期 ID 生成稳定幂等键，重复探测不得重复产生外部副作用。
- PostgreSQL 是生命周期与通知任务的唯一真相源；Redis/Dramatiq 只负责任务投递。
- Domain/Cognition 保持框架、ORM、任务库和厂商 SDK 无关。

### 验收标准

- 告警首次出现、持续、恢复和恢复后再次出现均形成正确生命周期，首次发生与恢复耗时可验证。
- 生命周期 API 仅返回当前 Agent 数据，状态、严重级别和渠道筛选有效。
- 升级配置可由管理后台发布；达到阈值后只形成一个稳定升级通知任务，关闭开关时不升级。
- 通知时间线能区分活动、升级和恢复事件；恢复通知兼容活动与升级前序事件。
- 可观测性总览展示生命周期聚合和按时间桶趋势，不泄露告警业务正文或任何密钥材料。
- Python 测试、Pyright、Ruff、格式检查、Alembic 单头和 Web lint/typecheck/test/build 全部通过。
