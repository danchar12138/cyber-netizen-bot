# 赛博网友机器人增量开发计划

> 版本：2026-09-10-v14
> 阶段：Telegram 首个真实 IM Adapter 与安全出站闭环
> 状态：已完成

## 目标

- 将 Telegram 从零副作用占位替换为首个真实 IM 出站 Adapter，保持统一渠道服务、加密凭证、限流、幂等结果和无正文诊断边界。
- 可靠支持连接测试、纯文本主动发送、话题线程回复和消息编辑；能力尚未打通时必须显式降级，不虚报媒体或入站能力。
- 管理后台可以完成实例、Token、连接测试和真实出站联调，不要求手改配置文件或手调 API。

## 实现大纲

1. 使用 `httpx` 实现正式 Telegram Adapter，固定官方 HTTPS 端点并隔离 Token 路径，校验 Bot Token、chat ID、话题 ID 和消息 ID。
2. 接通 `getMe`、`sendMessage` 与 `editMessageText`；限制单次一个、最多 4096 字符的纯文本消息，Markdown、附件和流式请求通过统一能力协商显式降级或拒绝。
3. 将远端限流、服务异常、网络错误、拒绝和非法响应转换为固定错误码；异常、日志、健康详情和诊断事件不得包含 Token、请求 URL、正文或 Telegram 原始错误。
4. 默认注册表将 Telegram 标记为正式实现，飞书和 Discord 继续保持零外部副作用占位；应用关闭时释放 Adapter HTTP 连接池。
5. 管理后台增加 Telegram 出站状态说明及可选择实例、填写 chat ID、话题 ID、编辑消息 ID 和正文的联调表单，并在发送前显式确认外部副作用。
6. 同步配置说明、API 文档、README、Web 测试数据和生成式客户端；增加 Adapter 成功、降级、校验、限流、异常及脱敏测试。

## 验收条件

- 缺失或格式错误的 Token、chat ID、话题 ID 和消息 ID 在发起网络请求前被安全拒绝。
- `getMe`、发送、编辑和话题映射通过无公网 MockTransport 测试；成功结果只返回稳定 Telegram message ID。
- 429、5xx、网络异常、拒绝和非法响应均使用安全错误码，Token、远端 description、正文及真实 Bot API URL 不进入异常、日志或诊断。
- Telegram 目录和实例显示正式可用，媒体及流式能力透明降级，真实入站明确拒绝；飞书和 Discord 仍不访问外部 API。
- Python、Web、Playwright、OpenAPI、生成式 SDK、包构建和 GitHub CI 全部通过。

## 暂不包含

- 不实现 Telegram Webhook、长轮询、签名网关或入站事件消费。
- 不读取 MinIO 附件二进制，不调用 `sendPhoto`、`sendDocument` 或反应接口。
- 不接入飞书、Discord 真实 API，也不引入自动远端重试，避免无平台幂等键时重复发送。
