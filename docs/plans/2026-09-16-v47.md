## 给 AI 的开发大纲

### 目标

在 v46 的校准草稿证据审计基础上，为管理后台提供资源类型和资源 ID 的服务端精确筛选，使管理员可以直接定位某个配置草稿的安全审计事件，同时保持租户隔离、只追加语义和敏感字段白名单。

### 实现范围

- 扩展管理审计仓储和应用服务，支持 `resource_type`、`resource_id` 精确过滤；模糊搜索继续保持兼容。
- 同步内存与 PostgreSQL 实现、API 查询参数、OpenAPI 和 TypeScript SDK。
- 管理后台审计日志增加操作、资源类型和资源 ID 筛选表单，查询结果仍只展示安全元数据。
- 补充应用单测、API 集成测试、Web 客户端测试和计划进度记录。

### 关键规则

- 资源过滤由服务端参数化查询执行，资源 ID 为完整字符串精确匹配，不使用客户端本地过滤代替授权边界。
- 查询继续限制在当前租户及允许查看的系统级审计范围，不回显 Secret、正文、Prompt、任务载荷或模型原始响应。
- 不改变审计记录追加式写入、分页排序和既有权限模型；未提供过滤条件时保持原有结果。
- Domain/Cognition 不依赖 FastAPI、SQLAlchemy、Dramatiq 或厂商 SDK。

### 验收标准

- 指定操作、资源类型和资源 ID 时只返回精确命中的审计记录；模糊搜索和分页行为保持稳定。
- API、OpenAPI、SDK、后台筛选、中文文案和测试保持一致。
- Ruff、Pyright、pytest、Web lint/typecheck/test/build、Playwright、OpenAPI 漂移、迁移 head 和差异检查通过。
- 使用中文 Conventional Commit 提交并推送到 `origin/main`。
