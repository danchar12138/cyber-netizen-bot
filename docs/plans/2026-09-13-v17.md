# 赛博网友机器人开发计划

> 版本：2026-09-13-v17  
> 阶段：Telegram 入站回复闭环与可靠出站投递  
> 状态：开发完成，进入下一阶段前的验证收口

## 目标

在 v16 Telegram 安全入站 Webhook、Inbox 和 Agent Run 闭环之上，打通“入站消息 -> 自研 Agent Run -> Telegram 回复”的完整链路。回复必须复用现有 `ChannelService.deliver()`，继续受渠道能力协商、凭证边界、限流、诊断事件和出站幂等机制保护。

## 实现范围

- Agent Run 仅在 `COMPLETED` 且最终 Agent 消息为 `COMPLETED`、正文非空时发送回复。
- `SUPPRESSED`、`FAILED`、`CANCELLED`、空正文以及仍处于 `QUEUED/RUNNING` 的 Run 不发送外部消息。
- 出站幂等键固定为 `inbound-reply:{tenant_id}:{channel_id}:{external_message_id}`，平台重试、Worker 重投和人工任务重放复用同一键。
- Telegram 收件人使用 `InboundEnvelope.external_conversation_id`；Forum 线程使用 `external_thread_id`，不从正文或显示名称推断路由。
- Worker 组合真实 `SqlAlchemyChannelRepository`、默认 Adapter Registry 和 `ChannelService`，注入 Telegram 入站回复分发器。
- 应用层新增回复消息查询端口；内存和 SQLAlchemy 实现都校验租户、Agent、用户会话成员关系、未删除会话以及 Agent 消息归属。
- 任务结果只返回发送状态、外部消息 ID 和是否幂等重放，不返回正文、Token、Webhook Secret 或远端原始响应。
- 出站失败向任务层传播，由可靠任务服务记录失败并按现有重试策略处理；不在本阶段引入平行的 Telegram 发送通道。

## 测试与验收

- 入站 Telegram 首次处理能够生成一次回复，且重复处理只产生一次外部发送。
- Telegram Forum 入站的会话 ID、线程 ID 和稳定幂等键正确传递到分发边界。
- Agent 抑制回复、空回复、失败或并发未完成 Run 均不会触发 Adapter。
- 回复消息查询拒绝错误租户、错误 Agent 和错误用户读取。
- 既有 Telegram Adapter 出站幂等、限流、错误脱敏和线程/编辑测试继续通过。
- `uv` 后端格式化、静态检查、类型检查、单元/集成测试和迁移头检查通过；Web API 契约、lint、类型、构建和端到端测试保持可运行。

## 下一阶段建议

下一阶段进入 Telegram 入站运营化：增加 Webhook 注册/状态探测、失败任务和出站事件的管理后台可视化、告警指标与可控人工重试，同时保持凭证和消息正文不可回显。
