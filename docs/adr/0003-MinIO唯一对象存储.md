# ADR 0003：使用 MinIO 作为唯一对象存储

> 状态：已接受
> 日期：2026-09-10

## 背景

附件上传、私有预览、多模态模型输入、数据清理和备份恢复都依赖一致的对象存储语义。同时维护多个后端会扩大配置、测试、安全和故障恢复矩阵，当前项目没有这一复杂度的业务收益。

## 决策

- MinIO 是项目唯一的附件与大对象存储；开发、测试和生产使用同一套 MinIO 语义与官方 Python SDK。
- 不实现 AWS S3 后端、自动回退或运行时后端切换，也不引入 `boto3`、`botocore` 或 `aioboto3`。
- 启动设置统一使用 `CNB_MINIO_*`；桶保持私有，浏览器通过短时预签名地址上传或预览。
- 服务端在绑定附件和送入模型前复核对象大小、MIME 与 SHA-256；生命周期清理和隔离恢复必须同时覆盖数据库元数据与 MinIO 对象。
- MinIO SDK 暴露的 `S3Error` 和 `x-amz-*` 属于其兼容协议细节，可以在基础设施实现中使用，但不得据此扩展为第二套对象存储实现。

## 结果

- 配置、部署、恢复演练和故障处置只维护一条经过验证的对象存储路径。
- 若未来确有新增后端的业务需求，需要新 ADR、独立适配器、完整迁移方案和等价验收，不得临时切换。
- MinIO 故障期间附件能力可以暂停，文本对话不应因此中断。

## 验证

- 架构契约测试禁止项目依赖清单声明 AWS 对象存储客户端，并检查启动字段只采用 `minio_*`。
- 对象存储单测、附件集成测试和基础设施验收覆盖预签名、摘要复核、私有桶、备份与隔离恢复。
