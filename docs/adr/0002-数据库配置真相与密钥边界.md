# ADR 0002：以数据库作为运行配置真相并隔离密钥

> 状态：已接受
> 日期：2026-09-10

## 背景

赛博网友需要频繁调整人格、模型路由、预算、任务、渠道与安全策略。若日常运行参数散落在环境变量或配置文件中，管理后台无法展示真实生效值，也难以完成校验、审计、发布和回滚。密钥若混入普通配置，又容易在 API、日志和导出中泄漏。

## 决策

- PostgreSQL 是可达数据库之后所有运行配置的唯一真相源，配置通过注册表定义键、类型、默认值、范围、作用域、敏感级别和生效方式。
- 新增运行设置必须同时提供定义、服务端验证、管理 API 与后台 UI，并进入草稿、差异、发布、历史和回滚闭环。
- 环境变量只承载连接数据库前必须可用的启动设置和秘密，例如数据库、Redis、MinIO、配置主密钥、正式身份引导与遥测出口。
- 普通运行配置按系统、租户、Agent、渠道和用户作用域解析；每次 Agent Run 冻结有效配置及认知资源版本，保证执行期间不漂移。
- 运行密钥由 SecretStore 加密保存，业务配置只保存引用或掩码。任何 API、日志、Trace、审计、导出和配置差异都不得返回已存密钥明文。

## 结果

- 常规运营和调优可在管理后台完成，具备统一校验、影响预览、审计和回滚能力。
- 启动设置变化仍可能需要重启进程，后台必须准确展示这一边界，不能假装热生效。
- 配置注册表、API 契约、后台表单和测试需要随新运行设置同步修改。

## 验证

- 配置注册表测试验证类型、范围、作用域和安全属性。
- SecretStore、配置 API 与 Web 测试验证密钥只写不读和掩码语义。
- 架构契约测试检查对象存储启动设置没有产生第二套后端命名。
